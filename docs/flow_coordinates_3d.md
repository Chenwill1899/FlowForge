# 分段流线坐标与名义控制：实现和验证

本轮基于 `refactor_benchmark` 的 `414f521` 实现。没有恢复此前被撤销的粗细域/重构改动，没有修改 2D 求解器或原有后处理。

## 分阶段实施

1. 新增误差计算，只作诊断，保留旧速度控制器。完整跑通 3D 后才进入第二阶段。
2. 替换名义速度为 `vt * u/|u| - Jdag * K * eta`，当前配置 `K = k_n I₂`，两个横向分量都参与反馈。保留旧签名和配置读取；`k_n_z_ratio` 不再作用于新的名义反馈。
3. 分别验证无界面、默认带 RViz 和 2D 回归。

入口仍是本项目的 `scripts/run_sim_paper.sh`（通过 `scripts/ros1_docker.sh`）。

## 实现范围

- `flow_coordinates_3d.h/.cpp`：冻结场采样、返回等势截面的积分、两维横向坐标、双步长数值雅可比、秩/条件数检查及名义控制。
- `fluid_guidance.h/.cpp`：每次成功细场更新时复制快照，采用原有分段参考起点作为三维锚点。场间隔内固定截面及基；不再用最近点偏移计算名义反馈。
- `gvf_manager.h/.cpp`：仅增加名义速度、最终速度和差值的记录；方向线回归、脱困、高度恢复、通道预判、限幅及安全处理未修改。
- `record_benchmark_trajectory.py`：在旧几何诊断列之后追加 `flow_eta_0/1/norm`、有效性、截面残差、雅可比和速度诊断。保留旧消息的读取兼容性。
- `test/flow_coordinates_3d_test.cpp` 与 `scripts/tests/check_flow_coordinates.py`：解析测试和实际运行检查。

数值场的总势使用 `(u_star.dot(x) - p(x))/v_cap`，不是将求解器存储的扰动势 `p` 当作总势。沿当前缓存速度的流线积分到该总势的锚点等值面；检查实际 `grad(phi).dot(u)>0`，不假定插值后仍恰有 `u=grad(phi)`。这与之前重新构造整个连续场的尝试不同。

雅可比使用步长 0.002 m 和 0.001 m 的中心差分，要求相对差异不超过 0.01、最小奇异值至少 1e-4、条件数不超过 1e3、伪逆残差不超过 1e-8，并检查切向残差。失败时新名义速度为零，不退回最近点反馈；原有下游处理仍可改变最终速度。

8 项 C++ 测试通过，日志 `logs/flow_coordinates/final_tests.log`。独立解析验证：

该运行中，有效控制的最大 `|Ju|=8.27696e-4`，最大 `|JJdag-I₂|=6.08094e-16`，最大名义衰减残差 `|J v_nom+K eta|=1.43223e-3`；误差计算平均 0.0315 ms，名义控制计算最大 1.4755 ms。

## 仍存在的数值条件限制

这轮对齐了现有数值流场上的截面返回误差和伪逆名义反馈，但没有证明原有插值实现满足论文的全部连续场假设：

- 原有三线性速度插值通常不等于三线性势插值的梯度。RViz 运行中记录的最大相对差异为 8.29984，不能忽略或称为已解决。
- 原有网格插值在单元界面不保证论文要求的全域 C1 正则性。运行时检查横截性、差分一致性及雅可比秩，不能代替完整的连续重构证明。
- 局部坐标不是所有状态均有效；本次没有为增加有效率而修改障碍域或安全处理。
- 原有后处理和无人机速度跟踪使实际误差动力学不同于理想名义控制；跨场刷新也可能出现坐标跳变。正常穿越不等于这些理论假设已全部满足。
